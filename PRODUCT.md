# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Next.js App Router, React, TypeScript, Tailwind CSS, Motion, GSAP with ScrollTrigger, ESLint, Git, GitHub, and Vercel.

Supabase is part of Peeraphon's preferred technology ecosystem and appears in factual project content, but it is not required for the portfolio implementation until there is a concrete persistent-data requirement.

## Users

Primary users are recruiters, internship reviewers, freelance clients, and technical collaborators evaluating Peeraphon Laoha's engineering work.

## Product Purpose

This product is Peeraphon Laoha's modern professional portfolio. It exists to demonstrate his ability to design and build practical full-stack and cross-platform software, with real projects serving as the primary proof of capability.

Success means visitors can understand within the first few seconds who Peeraphon is, what he builds, his core technical stack, and where to inspect his strongest work.

## Positioning

The portfolio positions Peeraphon as a Software Engineer and Full-stack Developer who builds practical, scalable web and cross-platform applications using Next.js, React, TypeScript, Supabase, Electron, cloud deployment, API integrations, and automation.

The site should prioritize project case studies and engineering capability over simply recreating a resume.

## Operating Context

Visitors arrive to evaluate Peeraphon for software engineering internships, full-stack, front-end, and web developer roles, freelance opportunities, or technical collaboration.

The homepage should quickly introduce Peeraphon, surface featured projects early, explain his technical capabilities, and provide a clear contact path through public email.

## Capabilities and Constraints

The portfolio must use factual, resume-based content only.

It must not invent metrics, clients, employment history, awards, certifications, user counts, revenue, years of professional experience, production scale, or project outcomes.

Public email may be used as the primary contact method. Phone number must remain hidden by default unless Peeraphon explicitly asks to expose it.

Featured projects must include GoodLife and JODJUM and should be presented as engineering case studies rather than generic project cards.

GoodLife is an ongoing student productivity and auto-sync platform for web and Windows Desktop using Next.js, TypeScript, Electron, Supabase, Moodle .ics parsing, LINE Messaging API, Cron jobs, and AI-assisted timetable scanning.

JODJUM is a task-management web application using Next.js and Supabase, with CRUD workflows, task status tracking, state handling, and cloud deployment.

Animation should support storytelling and hierarchy without compromising readability, accessibility, mobile usability, or performance.

Do not add or configure Supabase for the portfolio implementation until there is a verified dynamic feature such as contact-message storage or another persistent-data requirement.

## Brand Commitments

The site represents Peeraphon Laoha.

The experience should feel modern, premium, technical, and cinematic, with a target balance of roughly 70% professional and 30% visual wow factor.

The tone should be confident, concise, engineering-focused, human, and not arrogant.

## Evidence on Hand

Confirmed source content exists in `AGENTS.md`.

Current implementation includes centralized content in `src/data/profile.ts`, `src/data/projects.ts`, and `src/data/skills.ts`.

Known public URL from the resume context: `https://goodlife-delta.vercel.app`. Future work must not assume this is the final portfolio or GoodLife beyond what project context verifies.

No confirmed employers, clients, awards, certifications, user counts, revenue figures, performance metrics, or GitHub statistics are available.

## Product Principles

Lead with real work, not inflated claims.

Make engineering ability legible through project storytelling, technical decisions, and implementation quality.

Keep the experience visually memorable while protecting readability, responsiveness, accessibility, and performance.

Centralize factual content and links so future updates do not create inconsistent public claims.

Treat animation as product communication, not decoration.

## Accessibility & Inclusion

The portfolio should support semantic structure, keyboard-accessible navigation, visible focus states, sufficient contrast, meaningful link labels, and reduced-motion behavior.
